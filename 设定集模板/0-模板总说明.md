# 设定集模板总说明

本目录存放**数字柏林墙设定集**中每一类设定集文件的统一格式模板(共六类).所有设定文件应套用对应模板,以保证同类文件结构一致,便于浏览与检索.

## 一,目录结构与分类

| 目录 | 内容 | 对应模板 |
| --- | --- | --- |
| `世界观大纲/` | 世界观总纲性设定(历史,科技,地理,术语等) | [3-世界观设定集模板](3-世界观设定集模板.md) |
| `势力设定集/` | 各势力(组织/集团/教团)的设定 | [2-势力设定集模板](2-势力设定集模板.md) |
| `人物设定集/<势力名>/` | 各势力下人物的设定 | [1-人物设定集模板](1-人物设定集模板.md) |
| `武器与装备设定集/<势力名>/<装备类型>/` | 各势力的武器与装备设定 | [5-武器与装备设定集模板](5-武器与装备设定集模板.md)(分型骨架 [5a-枪械](5a-枪械模板.md)/[5b-近战武器](5b-近战武器模板.md)/[5c-爆炸物](5c-爆炸物模板.md)/[5d-平台与装具](5d-平台与装具模板.md)) |
| `孤章集/` | 独立成篇的叙事作品 | [4-孤章模板](4-孤章模板.md) |
| `数字柏林墙文档库/` | 世界内视角的文献与信件(报道,报告,信函,教材,诗等) | [6-文档库模板](6-文档库模板.md) |
| `派生视图/` | 由各文件登记字段自动生成的反向检索视图,**非设定正文**;本地生成物, 不入版本库 | 无(见 `工具/派生视图.js`) |

## 二,命名约定

1. **目录名,文件名一律使用中文名**,外文原名写入文件正文的标题行,形如 `# 中文名 (外文名)`.外文附注优先按该对象的**母语**撰写(如德语 `Raureif`,法语 `Jeanne d'Arc`,西语 `Caos`);母语写法不便或无需保留时音译为英语;未填写母语者直接按英语翻译附注.
2. 人物设定集路径为 `人物设定集/<势力中文名>/<人物中文名>.md`;势力名以 `势力设定集/` 下的文件名为准,中英对照见 `索引.md` 的势力名录(`索引.md` 为本地生成物,不入版本库).
3. 武器与装备设定集路径为 `武器与装备设定集/<势力中文名>/<装备类型>/<装备名称>.md`;装备类型为受控词表,取值为**单兵作战用品**"枪械/近战武器/爆炸物",**机动平台**"单兵外骨骼/战术载具/无人作战单元",**个体装具**"植入体与防护"与**其他**"电子战装备/其他".目录层级到此为止,不在装备类型之下再建子目录;需要按更细的类别(如手枪/步枪/机枪)检索时,改用装备文件自身的登记字段筛选.
   分型按**参数的量纲**划分,不设统摄性的"轻武器"大类:枪械以弹道与供弹计量,近战武器以刃长与挥砍动能计量,爆炸物以装药量与杀伤半径计量,三者不可共用一表;而"轻武器"在军事学上本就涵盖近战武器与手榴弹,用作目录名既不精确,也会使跨国籍检索时产生歧义.分型只落在目录名与 `**装备类型**` 字段上,若日后确需合并,只需移动目录,不涉及任何正文改写.
4. 同一势力在正文中若出现别名(如"企业联邦"="欧洲企业联合"),在**该势力文件自身的 `**别名**` 字段**中登记即可,正文不作强制统一;脚本会从该字段读取别名,无需在别处维护对照表.
5. 文件名中避免使用 `\ / : * ? " < > |` 与全角标点等符号;点号 `.md` 必须为半角.

## 三,标题层级约定

五类设定集统一使用三级标题结构,**不要跳级,不要把顶层章节写成多级并列**:

`@
# 文档标题(角色名/势力名/门类名/装备名/篇名)
## 一级章节(前言,基本信息,人物特征...)
### 二级章节(外貌特征,性格特质...)
#### 三级章节(子机构,子个体...)
`@

> 说明:人物,势力,世界观三类多为三级结构;武器与装备设定集为两级结构(`#` 标题 + `##` 章节).

## 四,内容填写约定

1. **未填写的内容**一律写 `(待补充)`,不要删除章节标题,以保证结构完整,便于逐项补写.
2. **可选章节**(如"前言""相关个体""备注")若确实不需要,整节删去或注明 `(本文无此项)`,不要留空.
3. 引用他人设定,进行角色联动时,须遵守 `CONTRIBUTING.md` 设定集撰写规范第五条(需原作者或管理员同意).
4. 本设定集不深挖"物质数据化"等违反客观规律设定的合理性(见 `CONTRIBUTING.md`).
5. 定量数据必须写明数值与单位,不得以"极高""大幅"等模糊表述代替.

## 五,跨文件引用约定

1. **一个文件只写它自己**.不要在文件里列出其他文件的名字:势力文件不列成员名单,人物文件不列登场作品.这类反向清单由 `工具/派生视图.js` 从登记字段自动生成至 `派生视图/`;该脚本与 `派生视图/` 均为本地生成物,不入版本库.
2. 每条关系只在**一方**声明:
   - 人物属于哪个势力 → 人物文件的 `**所属势力**`(同时须与所在目录一致)
   - 哪个角色在哪篇出场 → 篇目文件的 `**关联人物**`
   - 装备属谁 → 装备文件的 `**所属势力**`(同时须与所在目录一致)
3. 因此**新增文件不需要改动任何既有文件**.唯一例外是两个全局协作点:`历史年表.md`(新增年份事件)与 `术语与概念.md`(新增专有名词);这两份文件的末尾都设有 `## 追加区`,在其中**追加**一行即可,不要回头修改上方既有内容.
4. 登记字段的写法为 `**字段名** 值`,冒号须为半角,值不得为空;括注说明写在条目末尾的括号内,括注中不得出现 `,` 等列表分隔符.
5. 校验:`node 工具/派生视图.js --check` 会报告登记字段缺失,与路径不一致,关联名无对应文件等问题;只报告,不自动改写设定正文(该脚本为本地工具,不入版本库).
6. **引用分两类,写法不同**(见 `CONTRIBUTING.md` 02 格式一致性第四条):标注某条信息的出处用数字角标 `[^1]`,并在文末设 `## 引用来源` 节逐行写 `[^n]: `文件名``;"见 X""依据 X"一类导航引用写在行内,不占角标.两类引用都只写文件名,不写目录路径,且须指向仓库内现存的文件.

## 六,文件格式约定

1. 一律使用 **UTF-8 无 BOM** 编码.
2. 换行符使用 **LF**(仓库 `.gitattributes` 已设置 `* text=auto`,提交时自动归一化).
3. 仅接受 `.md`,或符合 `.md` 规范的 `.txt`.
4. 标点一律使用半角(见 `CONTRIBUTING.md` 02 格式一致性第五条): 逗号, 句号, 顿号, 分号, 冒号, 括号与引号均取半角, 斜杠用 `/`, 连接符用半角连字符 `-`, 省略号写 `...`; 仅书名号与间隔号保留原形.
